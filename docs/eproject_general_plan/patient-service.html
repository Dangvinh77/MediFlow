🧑‍⚕️ Patient Service

Vai trò: Quản lý thông tin nhân khẩu và hồ sơ bệnh nhân.

1. Trách nhiệm (Bounded Context)

  • Quản lý: Thông tin bệnh nhân (PATIENT), bao gồm cả BHYT.
  • Không quản lý: Lịch hẹn, hồ sơ bệnh án, thanh toán, thuốc.

2. Data Model

Bảng PATIENT

Trường Kiểu Mô tả
patient_id UUID (PK) Mã bệnh nhân
full_name VARCHAR(100) Họ tên
date_of_birth DATE Ngày sinh
gender ENUM('MALE','FEMALE') Giới tính
identity_number VARCHAR(20) UNIQUE Số CMND/CCCD
address VARCHAR(255) Địa chỉ
phone_number VARCHAR(15) Số điện thoại
email VARCHAR(100) Email
health_insurance_number VARCHAR(20) NULL Số BHYT (có thể NULL)
created_at TIMESTAMPTZ Ngày tạo
updated_at TIMESTAMPTZ Ngày cập nhật

3. API Endpoints

Method Path Request Response Auth Role
GET /api/v1/patients/{id} - PatientDTO ADMIN, DOCTOR, NURSE
GET /api/v1/patients page, size, keyword Page<PatientDTO> ADMIN, DOCTOR, NURSE
POST /api/v1/patients CreatePatientRequest PatientDTO ADMIN, NURSE
PUT /api/v1/patients/{id} UpdatePatientRequest PatientDTO ADMIN, NURSE
DELETE /api/v1/patients/{id} - 204 No Content ADMIN

Request/Response schemas:

CreatePatientRequest: { fullName, dateOfBirth, gender, identityNumber, address, phoneNumber, email, healthInsuranceNumber }
PatientDTO: { patientId, fullName, dateOfBirth, gender, identityNumber, address, phoneNumber, email, healthInsuranceNumber, createdAt, updatedAt }

4. Events Publish

Tên Event Schema Khi nào bắn
patient.created { patientId, fullName, email, phoneNumber } Khi tạo mới bệnh nhân
patient.updated { patientId, fullName, email, phoneNumber, address } Khi cập nhật thông tin

5. Events Subscribe

Từ Service Event Xử lý
Billing payment.completed Ghi log (không lưu thêm trong patient)

6. Business Rules / Validation

  • Số CMND/CCCD là duy nhất.
  • Email phải đúng định dạng (regex).
  • Số BHYT (nếu có) phải đúng format: XX-XXXXXXXX-X.
  • Ngày sinh không được lớn hơn ngày hiện tại.
  • Số điện thoại chỉ chứa số, tối thiểu 10 số.

7. Sequence Diagram – Tạo bệnh nhân

Client → Gateway → Patient Service
1. POST /api/v1/patients (kèm body)
2. Patient Service: validate dữ liệu
3. Lưu vào DB
4. Publish patient.created → RabbitMQ
5. Trả về PatientDTO cho Client
