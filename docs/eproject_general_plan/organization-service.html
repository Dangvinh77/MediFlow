🏢 Organization Service

Vai trò: Cơ cấu tổ chức của bệnh viện — có những khoa/phòng nào, ai làm việc ở đâu, và họ đăng nhập bằng gì.

Service này là nền của toàn hệ thống. Nó sở hữu ba thứ mà mọi service khác tham chiếu tới: DEPARTMENT (phòng ban), STAFF (chính là staff_id xuất hiện trong lịch hẹn, hồ sơ và đơn thuốc), và ACCOUNT (nơi Gateway đối chiếu để cấp JWT). Không có nó thì không có khái niệm phòng ban, không ai sở hữu bác sĩ, và không có kho người dùng để xác thực.

1. Trách nhiệm (Bounded Context)

  • Quản lý: Khoa/phòng (DEPARTMENT), nhân viên y tế (STAFF), tài khoản đăng nhập (ACCOUNT).
  • Không quản lý: Bệnh nhân, lịch hẹn, hồ sơ, xét nghiệm, thuốc, tiền. Service này trả lời ai và ở đâu, không bao giờ trả lời điều gì đã xảy ra với bệnh nhân.

2. Data Model

DEPARTMENT — khoa / phòng ban

Trường Kiểu Mô tả
department_id UUID (PK) Mã khoa
department_name VARCHAR(100) Tên khoa (VD: Khoa Nội tổng hợp)
abbreviation VARCHAR(20) UNIQUE Mã viết tắt (VD: NOI, NGOAI, XN)
department_type ENUM('CLINICAL','PARACLINICAL','ADMINISTRATIVE') Phân loại khoa
department_head_id UUID (FK → STAFF, nullable) Trưởng khoa
location VARCHAR(255) Vị trí (tầng, tòa nhà)
is_active BOOLEAN Khoa còn hoạt động không
created_at / updated_at TIMESTAMPTZ -

STAFF — nhân viên y tế

Trường Kiểu Mô tả
staff_id UUID (PK) Mã nhân viên — chính là staff_id mà các service khác tham chiếu
full_name VARCHAR(100) Họ tên
department_id UUID (FK — cùng service) Thuộc khoa nào
job_title ENUM('DOCTOR','NURSE','TECHNICIAN','PHARMACIST','CASHIER','MANAGER','ADMINISTRATIVE') Chức danh
specialization VARCHAR(100) NULL Chuyên khoa sâu
license_number VARCHAR(50) NULL Số chứng chỉ hành nghề
phone_number VARCHAR(15) -
email VARCHAR(100) -
status ENUM('ACTIVE','INACTIVE') -
created_at / updated_at TIMESTAMPTZ -

ACCOUNT — tài khoản đăng nhập

Trường Kiểu Mô tả
account_id UUID (PK) -
username VARCHAR(50) UNIQUE Tên đăng nhập
password_hash VARCHAR(255) BCrypt hash — không bao giờ lưu plaintext, không bao giờ ghi log
staff_id UUID (FK — cùng service, nullable) Null với tài khoản vai trò PATIENT
role ENUM('ADMIN','DOCTOR','NURSE','PHARMACIST','CASHIER','LAB_TECH','MANAGER','PATIENT','SYSTEM') Khớp chính xác với Roles.java
is_active BOOLEAN -
last_login_at TIMESTAMPTZ NULL -
created_at / updated_at TIMESTAMPTZ -

3. API Endpoints

Method Path Request Response Auth Role
GET /api/v1/org/departments - List<DepartmentDTO> ADMIN, MANAGER, DOCTOR, NURSE
GET /api/v1/org/departments/{id} - DepartmentDTO ADMIN, MANAGER, DOCTOR, NURSE
POST /api/v1/org/departments CreateDepartmentRequest DepartmentDTO ADMIN
PUT /api/v1/org/departments/{id} UpdateDepartmentRequest DepartmentDTO ADMIN
GET /api/v1/org/staff?departmentId&jobTitle&page&size - Page<StaffDTO> ADMIN, MANAGER, DOCTOR, NURSE
GET /api/v1/org/staff/{id} - StaffDTO ADMIN, MANAGER, DOCTOR, NURSE
POST /api/v1/org/staff CreateStaffRequest StaffDTO ADMIN
PUT /api/v1/org/staff/{id} UpdateStaffRequest StaffDTO ADMIN
PUT /api/v1/org/staff/{id}/department { departmentId } StaffDTO ADMIN
GET /api/v1/org/staff/{id}/exists - { exists, departmentId } SYSTEM (nội bộ)
POST /api/v1/org/accounts CreateAccountRequest AccountDTO ADMIN
PUT /api/v1/org/accounts/{id}/status { isActive } AccountDTO ADMIN
POST /api/v1/org/accounts/verify { username, password } { accountId, staffId, departmentId, role } SYSTEM (chỉ Gateway)
/accounts/verify là thứ biến auth stub của Gateway thành xác thực thật: Gateway gửi thông tin đăng nhập, service này kiểm tra hash rồi trả về danh tính, Gateway mới ký JWT. Gateway tuyệt đối không đọc thẳng bảng ACCOUNT — đó sẽ là truy cập DB chéo service.

4. Events Publish

Tên Event Schema Khi nào bắn
department.created { departmentId, departmentName, departmentType } Khi tạo khoa mới
staff.created { staffId, fullName, departmentId, jobTitle } Khi thêm nhân viên
staff.department.changed { staffId, oldDepartmentId, newDepartmentId } Khi điều chuyển nhân viên giữa khoa

5. Events Subscribe

Không có. Đây là dữ liệu nền — nó điều khiển các context khác chứ không phản ứng theo chúng.

6. Business Rules

  • username là duy nhất; mật khẩu lưu dạng BCrypt hash, không bao giờ plaintext, không bao giờ ghi log.
  • Một STAFF phải thuộc đúng một DEPARTMENT đang hoạt động.
  • job_title = DOCTOR bắt buộc phải có license_number (chứng chỉ hành nghề).
  • department_head_id nếu có phải là STAFF thuộc chính khoa đó.
  • Không thể đặt is_active = false cho khoa còn nhân viên đang làm việc.
  • Điều chuyển nhân viên phải publish staff.department.changed; không được xóa rồi tạo lại.
  • Tài khoản vai trò PATIENT không có staff_id (bệnh nhân không phải nhân viên).
  • Vô hiệu hóa tài khoản phải chặn được lần đăng nhập kế tiếp; JWT đã cấp sẽ hết hạn tự nhiên.

7. Chiều phòng ban xuyên suốt hệ thống

department_id được mang theo trong mọi bảng nghiệp vụ và mọi event, nhờ đó hệ thống trả lời được những câu hỏi định nghĩa một hệ thống theo phòng ban:

Câu hỏi Cần dữ liệu
Khoa nào chỉ định xét nghiệm này? LAB_TEST.department_id
Doanh thu từng khoa trong tháng BILLING.department_id + tổng hợp ở Report
Khoa Nội có những bác sĩ nào, ai là trưởng khoa? STAFF.department_id, DEPARTMENT.department_head_id
Điều chuyển bác sĩ từ Khoa Nội sang Khoa Ngoại staff.department.changed
Người dùng này được phép làm gì? ACCOUNT.role, xác định lúc đăng nhập

Các service khác giữ department_id dưới dạng UUID trần — không có quan hệ JPA, không join chéo database.

8. Sequence Diagram – Đăng nhập

Client → Gateway → Organization Service
1. POST /api/v1/auth/login { username, password }
2. Gateway → POST /api/v1/org/accounts/verify
3. Organization: tìm ACCOUNT theo username
4. Organization: so khớp BCrypt hash, kiểm tra is_active
5. Organization → { accountId, staffId, departmentId, role }
6. Gateway ký JWT với claim: sub, role, departmentId, exp
7. Trả về { accessToken, refreshToken, role }
