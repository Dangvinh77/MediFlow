🛡️ Gateway Service

Vai trò: API Gateway – điểm vào duy nhất cho tất cả client, đảm bảo xác thực, phân quyền, định tuyến, rate limiting, và log tập trung.

1. Trách nhiệm (Bounded Context)

  • Quản lý: Xác thực (JWT), phân quyền (RBAC), định tuyến request đến service đích, giới hạn tần suất, ghi log.
  • Không quản lý: Nghiệp vụ y tế, dữ liệu bệnh nhân, thuốc, thanh toán…

2. Data Model

Gateway không lưu trữ dữ liệu nghiệp vụ, chỉ lưu cấu hình route, danh sách service từ Service Registry (Eureka).

Cấu hình route:

Trường Kiểu Mô tả
route_id UUID (PK) ID route
path VARCHAR(200) Đường dẫn (VD: /api/v1/patients/**)
service_name VARCHAR(50) Tên service (patient-service, ...)
method ENUM GET, POST, PUT, PATCH, DELETE, OPTIONS
roles_allowed SET<ENUM> Danh sách role được phép truy cập route

3. API Endpoints (Gateway tự thân)

Gateway chỉ cung cấp endpoints cho authentication và health check.

Method Path Request Response Auth
POST /api/v1/auth/login { username, password } { accessToken, refreshToken, role } Public
Gateway không lưu người dùng. Nó gọi POST /api/v1/org/accounts/verify tới Organization Service để đối chiếu mật khẩu, rồi mới ký JWT với claim sub, role, departmentId, exp. Đọc thẳng bảng ACCOUNT sẽ là truy cập DB chéo service — bị cấm.
POST /api/v1/auth/refresh { refreshToken } { accessToken } Public
GET /actuator/health - { status } Internal

4. Account Verification Contract

Gateway không truy cập trực tiếp database của Organization Service. Gateway gọi endpoint nội bộ để xác thực tài khoản.

Request:

POST /api/v1/org/accounts/verify

{
  "username": "admin",
  "password": "password"
}

Response:

{
  "accountId": "uuid",
  "staffId": "uuid",
  "departmentId": "uuid",
  "role": "ADMIN"
}

Các field accountId, staffId, departmentId và role phải được thống nhất giữa Organization Service, Gateway và JWT.

5. Events Publish / Subscribe

Gateway không publish/subscribe event nghiệp vụ; chỉ lắng nghe sự kiện khởi tạo từ Service Registry để cập nhật route động.

6. Business Rules / Validation

  • Token JWT phải còn hạn và chứa claim role.
  • Mỗi request phải có header Authorization: Bearer <token> (trừ login/refresh).
  • Rate limiting: tối đa 100 request/phút cho mỗi client IP.
  • Route chỉ chuyển tiếp nếu service đích có trong Service Registry.
  • Role trong JWT phải thuộc danh sách role chuẩn của hệ thống.
  • Gateway không được tin tưởng các identity headers do client tự gửi.
  • Gateway phải ghi đè identity headers bằng thông tin lấy từ JWT.
  • Downstream Service vẫn phải tự kiểm tra authorization.

7. JWT Claims

Claim Mô tả
sub Account identifier của user đã xác thực
role Vai trò của user
departmentId ID khoa/phòng của user nếu có
exp Thời điểm JWT hết hạn

8. Request Headers

Sau khi validate JWT thành công, Gateway truyền thông tin identity xuống các downstream services.

Header Mô tả
X-User-Id Authenticated account identifier
X-User-Role Authenticated user role
X-Department-Id Authenticated user's department identifier
X-Correlation-Id Request tracing identifier
Client không được phép tự quyết định X-User-Id, X-User-Role hoặc X-Department-Id. Gateway phải xóa hoặc ghi đè các header này trước khi forward request.

9. Sequence Diagram – Xác thực và gọi API

Client → Gateway: POST /api/v1/auth/login
Gateway → Organization Service: POST /api/v1/org/accounts/verify
    → đối chiếu BCrypt hash, trả { accountId, staffId, departmentId, role }
Gateway ← Organization Service: account verification result
Gateway →: ký JWT với claims { sub, role, departmentId, exp }
Gateway → Client: trả về { accessToken, refreshToken, role }

Client → Gateway: GET /api/v1/patients (kèm token)
Gateway: validate token, kiểm tra role, lấy route từ registry
Gateway → Patient Service: chuyển tiếp request
Patient Service: kiểm tra authorization và xử lý business logic
Patient Service → Gateway: response
Gateway → Client: trả về kết quả

10. Downstream Service Security

Gateway là lớp bảo mật đầu tiên nhưng không phải lớp bảo mật duy nhất. Các downstream services vẫn phải tự xác thực authorization.

Client
  ↓
Gateway
  ↓ Authentication + RBAC
Patient Service
  ↓ Authorization verification
Business Logic

Điều này đảm bảo request không thể bypass security của service chỉ vì Gateway đã xác thực JWT trước đó.
