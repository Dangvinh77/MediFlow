💊 Pharmacy Service — Technical Design (Coding Reference)

Module: backend/pharmacy-service/ · Package: com.mediflow.pharmacy · Cổng: 8085 · DB: mediflow_pharmacy · Base path: /api/v1/pharmacy

Vai trò: Quản lý thuốc, tồn kho, đơn thuốc và phiếu xuất. Thành phần tham gia Saga kê đơn → hóa đơn → thanh toán → xuất thuốc. Service duy nhất có thể hết hàng.

Nguồn đồng bộ: file này là tài liệu tham chiếu code; bản markdown tương ứng docs/eproject_general_plan/backend-spec/05-pharmacy.md (giữ nếu cần, không bắt buộc).

Kiến trúc (hexagonal): application → domain, phụ thuộc hướng vào trong. Driving adapter web/ (HTTP) và messaging/consumer/ (events) gọi vào application; driven adapter infrastructure/ (persistence, messaging publisher, security, config) hiện thực out-port của application.

1. Bounded Context & Trách nhiệm

  • Sở hữu: Danh mục thuốc (DRUG), tồn kho, đơn thuốc (PRESCRIPTION), dòng kê (PRESCRIPTION_LINE), phiếu xuất (DISPENSE_SLIP).
  • Không sở hữu: Thanh toán (billing), hồ sơ (clinical), thông tin bệnh nhân (patient).
  • Saga participant: nhận payment.completed để xuất thuốc; phát prescription.dispense.failed để billing bù trừ.

CREATE TABLE DRUG ( drug_id UUID PRIMARY KEY, drug_name VARCHAR(150) NOT NULL, active_ingredient VARCHAR(150), unit VARCHAR(20) NOT NULL, price DECIMAL(15,2) NOT NULL, stock_quantity INT NOT NULL DEFAULT 0, expiry_date DATE NOT NULL, manufacturer VARCHAR(150), low_stock_threshold INT NOT NULL DEFAULT 10, created_at TIMESTAMPTZ NOT NULL DEFAULT now(), updated_at TIMESTAMPTZ, CONSTRAINT ck_drug_price_positive CHECK (price >= 0), CONSTRAINT ck_drug_stock_non_negative CHECK (stock_quantity >= 0) ); CREATE INDEX idx_drug_name ON DRUG (drug_name); CREATE TABLE PRESCRIPTION ( prescription_id UUID PRIMARY KEY, record_id UUID NOT NULL, -- ref clinical patient_id UUID NOT NULL, -- ref patient doctor_id UUID NOT NULL, -- ref organization NHAN_VIEN department_id UUID NOT NULL, -- ref organization KHOA prescribed_date DATE NOT NULL, total_amount DECIMAL(15,2) NOT NULL DEFAULT 0, created_at TIMESTAMPTZ NOT NULL DEFAULT now(), updated_at TIMESTAMPTZ ); 8. Thuật toán tầng Application

createPrescription — @Transactional

  1. Mỗi dòng: drugRepo.findById(drugId) → không có thì DRUG_NOT_FOUND.
  2. Chụp giá: unitPrice = drug.getPrice() — client không được đặt giá.
  3. Dựng PrescriptionLine; lineTotal = unitPrice × quantity (HALF_UP, 2 chữ số).
  4. Prescription.create(...) → tính totalAmount (BR-D5).
  5. Lưu đơn thuốc.
  6. DispenseSlip.createPending(prescriptionId) → lưu (BR-D3 — luôn PENDING).
  7. Publish PrescriptionCreatedEvent sau commit → billing tạo hóa đơn.
KHÔNG trừ kho ở đây. Kê đơn chỉ là ghi nhận ý định. Kho chỉ biến động lúc xuất thuốc sau khi thanh toán. Trừ kho hai lần là lỗi dễ gặp nhất.

dispense(prescriptionId, dispensedBy) — @Transactional

Gọi từ cả PUT /prescriptions/{id}/dispense lẫn consumer của payment.completed.

  1. dispenseSlipRepo.findByPrescription(prescriptionId) → không có thì DISPENSE_NOT_FOUND.
  2. nếu !slip.isPending() → DISPENSE_ALREADY_DONE (idempotent: redelivery không xuất 2 lần).
  3. Nạp đơn thuốc + các dòng.
  4. Sắp xếp dòng theo drugId trước khi khóa — tránh deadlock.
  5. Mỗi dòng: drugRepo.findByIdForUpdate(drugId) → drug.dispenseStock(quantity); ném DRUG_OUT_OF_STOCK / DRUG_EXPIRED.
  6. Khi lỗi: trừ kho rollback, slip.markFailed(reason), lưu phiếu REQUIRES_NEW, publish PrescriptionDispenseFailedEvent → billing bù trừ (BR-D6).
  7. Thành công: lưu từng thuốc; slip.markDispensed(dispensedBy, now); lưu.
  8. Thuốc nào belowLowStockThreshold() → publish StockLowEvent.
  9. Publish PrescriptionFilledEvent sau commit.
Bước 6 là nhánh bù trừ. Phiếu xuất vẫn phải ghi FAILED dù transaction trừ kho rollback — cần REQUIRES_NEW. Làm sai thì saga treo vĩnh viễn.

onPaymentCompleted(prescriptionId, invoiceId)

  1. processed.alreadyProcessed(eventId) → return.
  2. gọi dispense(prescriptionId, SYSTEM_USER).
  3. processed.markProcessed(...) trong cùng transaction.
  4. Lỗi nghiệp vụ không ném ngược lại Rabbit (đã publish dispense.failed); chỉ lỗi hạ tầng mới vào dead-letter.

9. Tương tranh — đọc kỹ trước khi viết dispense

Hai dược sĩ xuất cùng thuốc cùng lúc sẽ bán vượt tồn kho nếu không khóa. CHECK (stock_quantity >= 0) chỉ là phòng thủ cuối.

@Lock(LockModeType.PESSIMISTIC_WRITE) @Query("SELECT d FROM DrugJpaEntity d WHERE d.drugId = :id") Optional<DrugJpaEntity> findByIdForUpdate(@Param("id") UUID id);
  • Luôn khóa qua findByIdForUpdate trong dispense — không dùng findById thường.
  • Luôn khóa dòng đã sắp xếp theo drugId.
  • Giữ transaction ngắn: không gọi REST, không publish event trong lúc giữ khóa.
