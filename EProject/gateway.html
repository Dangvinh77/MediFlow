🛡️ Gateway Service

Vai trò: API Gateway – điểm vào duy nhất cho tất cả client, đảm bảo xác thực, phân quyền, định tuyến, rate limiting, và log tập trung.

1. Trách nhiệm (Bounded Context)

  • Quản lý: Xác thực (JWT), phân quyền (RBAC), định tuyến request đến service đích, giới hạn tần suất, ghi log.
  • Không quản lý: Nghiệp vụ y tế, dữ liệu bệnh nhân, thuốc, thanh toán…

2. Data Model

Gateway không lưu trữ dữ liệu nghiệp vụ, chỉ lưu cấu hình route, danh sách service từ Service Registry (Eureka).

Bảng cấu hình route (trong database config):

TrườngKiểuMô tả
route_idUUID (PK)ID route
pathVARCHAR(200)Đường dẫn (VD: /api/v1/patients/**)
service_nameVARCHAR(50)Tên service (patient-service, ...)
methodVARCHAR(10)GET, POST, PUT, DELETE
roles_allowedTEXTDanh sách role (ADMIN, DOCTOR,...)

3. API Endpoints (Gateway tự thân)

Gateway chỉ cung cấp endpoints cho authentication và health check.

MethodPathRequestResponseAuth
POST/api/v1/auth/login{ username, password }{ accessToken, refreshToken, role }Public
Gateway không lưu người dùng. Nó gọi POST /api/v1/org/accounts/verify tới Organization Service để đối chiếu mật khẩu, rồi mới ký JWT với claim sub, role, maKhoa, exp. Đọc thẳng bảng TAI_KHOAN sẽ là truy cập DB chéo service — bị cấm.
POST/api/v1/auth/refresh{ refreshToken }{ accessToken }Public
GET/actuator/health-{ status }Internal

4. Events Publish / Subscribe

Gateway không publish/subscribe event nghiệp vụ; chỉ lắng nghe sự kiện khởi tạo từ Service Registry để cập nhật route động.

5. Business Rules / Validation

  • Token JWT phải còn hạn và chứa claim role.
  • Mỗi request phải có header Authorization: Bearer <token> (trừ login/refresh).
  • Rate limiting: tối đa 100 request/phút cho mỗi client IP.
  • Route chỉ chuyển tiếp nếu service đích có trong Service Registry.

6. Sequence Diagram – Xác thực và gọi API

Client → Gateway: POST /auth/login
Gateway → Organization Service: POST /api/v1/org/accounts/verify
    → đối chiếu BCrypt hash, trả { maTaiKhoan, maNhanVien, maKhoa, vaiTro }
Gateway ←: trả về JWT
Client → Gateway: GET /api/v1/patients (kèm token)
Gateway: validate token, kiểm tra role, lấy route từ registry
Gateway → Patient Service: chuyển tiếp request
Patient Service → Gateway: response
Gateway → Client: trả về kết quả
