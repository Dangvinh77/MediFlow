# Clinical V1 producer fixture

`appointment.status.changed.v1.json` is copied byte-for-byte from the real clinical-service producer
fixture at `backend/clinical-service/src/test/resources/contracts/appointment.status.changed.v1.json`.
Do not edit this file by hand; pull a fresh copy if clinical-service changes the wire shape.

Exchange `mediflow.events`, producer `clinical-service`, envelope `version=1`, routing key
`appointment.status.changed` equal to `eventType`. This exact fixture is the normal check-in
transition: `oldStatus=PENDING`, `newStatus=AWAITING_PAYMENT`, `sourceType=EXAM`,
`sourceId=appointmentId=careEpisodeId`, `recordId=null` (before examination starts).

Clinical reuses this same routing key for every other appointment status transition (`startExam`,
`complete`, `onFinancialClearance`), always with `sourceType=EXAM`, but only this exact
`newStatus=AWAITING_PAYMENT` shape is the EXAM charge trigger; every other transition is valid but
not applicable to Billing's issuer (`ExamChargeDecoder#decodeApplicable` returns empty for them, not
a fixture — Clinical has not committed one of those, and Billing does not guess their bytes).
